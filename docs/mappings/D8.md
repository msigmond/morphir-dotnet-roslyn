# D8 — enum and tuple mapping

The fixed baseline remains C#14, Roslyn5.0.0 and .NET10.0.0 x64. [D8 state](../deliveries/D8-state.md) records the gate results; this mapping alone is not a completion claim.

## Enums

A selected source enum is a custom type with one constructor wrapping its exact underlying numeric domain. The type and constructor belong to the namespace/enclosing-type module; constants belong to the enum member module. For Example.D8.Access, these identities are Example.D8.Access for data/constructor and Example.D8.Access.read for the Read value. Every declared constant, alias, private declaration and documentation is retained, independently of compiler constant folding. Field symbol identities include the containing type; identically named constants in different enums stay distinct.

All eight legal underlying types retain their full source domain, including unnamed values and zero even if no constant names it. Int64/UInt64 use the D5 exact limb representation. Flags are numeric operations, with the same width, wrapping, promotions and conversions as the underlying CLR type; an enum never becomes a closed union of named values. Equality compares complete wrapped numeric values. Numeric casts, complement, arithmetic, bitwise operators and nullable lifting reuse the delivered numeric/Decimal mappings and failure proofs. Explicit or compilation-enabled checked operations still reject. Exact baseline FlagsAttribute is declarative metadata; unrelated attributes reject.

## Tuples

Value tuples use ordered Classic Tuple types/values/patterns. Source labels resolve element positions and do not introduce fields or runtime reconstruction. Nested and long tuples retain order; ItemN and reference-tuple Rest map to their actual slots. Exact System.Tuple/ValueTuple constructors and Create factories are scoped framework mappings, independent of general class/generic support. Eight-argument reference factories construct their nested rest tuple. The baseline constructor enforces a nonnull tuple Rest; that specific slot carries its framework construction invariant, while ItemN reference slots still use Maybe. Explicit rest construction requires the correct tuple family and a present reference rest; invalid constructor inputs reject instead of fabricating successful tuples.

Reference tuples use Maybe despite annotations. Value-tuple elements retain each element's default and M1 contract, including null reference slots; default reference tuples are Nothing. A guard, construction, or validated immutable origin must prove every dereference. Null-forgiving syntax supplies no proof. Nullable tuple conversions map each present element and preserve absence. Tuple element conversions retain numeric width/rounding/failure contracts, rather than merely changing an IR attribute.

Deconstruction snapshots the complete right-hand value before sequential binding, handles nested targets/discards and applies destination conversions. Local/by-value value-tuple element updates rebuild immutable binding versions; copies preserve their prior values. Input/external reference updates remain subject to later ownership/alias gates. Tuple equality evaluates source operands in order, compares elements using their delivered source operators, and short-circuits comparisons. Nullable equality preserves absence; IEEE NaN and signed-zero behavior is retained. Unknown user operators and reference identity are not replaced by structural equality.

## Model and independent evidence

Classic now separates type definitions from specifications. Alias and custom definitions, public custom specifications, and opaque specifications preserve the pinned codec's access-controlled constructor dictionaries. Public specifications hide private constructors and exclude private declarations. Existing alias JSON remains identical. The two production compatibility factories were mechanically re-emitted from unchanged independently compiled Elm IR after this typed model migration; only factory C# types and their generated-byte hashes changed. Their source/IR and all prior golden references remain unchanged.

New references are separately authored ordinary Elm enum output and complete original Elm codec distributions for tuple operations, flags with their full helper modules, custom/opaque specifications, and the cumulative project. Provenance records exact source, modes, pinned toolchain and hashes. Validation never writes references. EnumTupleTests compares emitted CLR behavior at numeric boundaries, aliases/unnamed values, nullable inputs, tuple copying, deconstruction, evaluation order, equality, default slots and null/safety failures. Later general class/generic/collection/dispatch/API closure remains gated by the master plan.
