# D10 — Generic declarations and calls

The user approved this profile on 2026-11-01. The [exact Elm contract](../elm-parity.md) controls acceptance.

Unconstrained type parameters map to Elm type variables. Generic data map to parameterized aliases.
Method and local function declarations keep their type variables. Calls and method references use the resolved type arguments.
Alias field reads, constructors, getters, updates, and delegates use the same substitution.
Local declarations keep their annotated signature. Their lambda body types follow resolved uses,
as in the pinned Elm compiler. Conflicting local body types are rejected by both frontends.
Unused generic locals, including references only from other unused locals, need a separate mapping
for the compiler-generated body type-variable names. They remain explicitly rejected.
Nested aliases list outer parameters before their own parameters.

Owners use declaration names, without constructed type arguments. No type is copied for each instantiation.
Overloaded method names keep the approved signature suffix. Type names that collide across arities are rejected.
Parameter names that collide in a scope, or imply an Elm number/comparable/appendable constraint, are rejected.
Names are not changed to avoid a collision.

Constraints, variance, interfaces, abstract/virtual/override members, inheritance, base access,
casts to base/interface types, and runtime type tests retain explicit rejection.
Unused method type parameters have no Elm signature variable and remain rejected.
Generic default values, type-parameter construction, and unapproved metadata calls also remain rejected.
There are no generated dispatch bodies or runtime alternatives.
