## Ordinary generic values

Selected static functions, readonly positional record structs and their explicit receiver methods retain ordinary IR variables. Constructed call signatures substitute both containing-type and method arguments; they do not create one declaration per concrete invocation. Nested type arguments include their enclosing type arguments. Generic reference arguments carry their existing Maybe representation, including nullable and nonnullable String slots under M1.

Sibling types with the same source name and different arities receive explicit arity suffixes; an unambiguous ordinary type name stays unchanged. Shadowed method/type parameters have distinct IR variables, including nested local method scopes.

Roslyn validates constraint satisfaction. Constraints on bodies that only transport their arguments need no runtime witness: struct, unmanaged, class/class?, notnull and new() constraints can accompany such parametric bodies. A constraint does not license a fabricated default, construction or dispatch. Type-dependent operations use explicit default, creation and absence witnesses as described below. Variance and ref-like generic parameters retain explicit gates.

Resolved generic method references use instantiated signatures and the existing pure Func mapping. External generic framework methods retain their exact catalog gates. No matching-name inference is introduced.
