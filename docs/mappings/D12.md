# D12 — Patterns and returned switches

The user approved this profile on 2026-11-01. The [exact Elm contract](../elm-parity.md) applies.

| C# form | Elm mapping |
| --- | --- |
| Switch expression; final value-returning switch statement | case / PatternMatch |
| Bool, Char, String, nonnegative whole-number, and Float literal patterns | LiteralPattern |
| Enum case member | LiteralPattern with the declared Int value and enum alias type |
| Explicit nullable null; non-null literal/tuple/list patterns | Nothing; Just pattern |
| Discard; var binding | WildcardPattern; AsPattern |
| Tuple patterns; whole-pattern names | TuplePattern; AsPattern |
| Empty list; explicit prefix and final tail slice | EmptyListPattern; HeadTailPattern |

Case order is source order, including an early default label.
A missing default stays missing. No match-success proof or fallback is added.
Each switch statement section must return a value. The switch must be in final value position.
Declared result contexts apply to each arm, including the approved Just conversion.
Pattern variables have case scope. Names must remain distinct after Morphir conversion.
The existing D4 is-null/is-not-null operations keep their comparison mapping.
Other is-pattern expressions need another mapping.

Guards, relational/logical patterns, property/record positional patterns, runtime type/declaration tests,
grouped labels, break/goto/following statements, and void switches remain rejected.
Only a final list slice is mapped. Middle/suffix slices need another representation.
Null switch patterns require an explicit nullable input. Nullable extraction still needs an approved fallback.
Computed/default/non-enum named constants, Decimal patterns, and implicit carrier conversions remain rejected.
The pinned parser rejects negative literal patterns, including parenthesized forms.
Negative enum case values therefore remain rejected as patterns.
Written whole-number literals must remain exact in the pinned compiler JSON number representation.
These are literal-format limits. No checks are added to runtime values.
C# unary minus retains its existing Basics.negate/Decimal.negate mapping, including signed literal values.

The standard LiteralPattern model/codec node is added. The envelope remains Classic v3.
Exact case IDs: `d12-literals`, `d12-patterns`, `d12-statements`, `d12-nested`, and `current-sample`.
