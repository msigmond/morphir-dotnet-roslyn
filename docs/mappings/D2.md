# D2 — project inputs, source graph and qualified calls

Status: passed; prerequisite D1 passed. Core semantics remain in `Morphir.Frontend.CSharp`; project acquisition/build/generator orchestration lives in `Morphir.Frontend.CSharp.ProjectSystem`, and CLI serialization stays in the adapter. No DLL-body translation or purity inference is introduced.

## Input/proof contract

`ProjectLoader.LoadAsync(path, ProjectSettings)` requires an explicit `net10.0` target and configuration (Debug default). It verifies the actual project build without restoring/upgrading packages, then uses Roslyn 5.0.0 MSBuildWorkspace with the pinned SDK 10.0.100. Compilation options, language/preprocessor symbols, nullable/overflow/platform settings, metadata references, project-reference aliases/embedding, AdditionalFiles and analyzer configuration come from evaluated MSBuild inputs. Compiler/generator/analyzer errors and missing inputs fail before conversion. Builds disable reusable worker nodes to prevent background MSBuild processes holding redirected output streams open.

Workspace source Documents are copied into a fresh compilation for each source project. Referenced projects recursively supply CompilationReferences; no source joining or DLL disassembly occurs. An explicit CSharpGeneratorDriver runs every configured generator with the actual parse/options/additional-file/config provider; generated trees are retained once. Generator loading/failure diagnostics are fatal, including generator exceptions reported as compiler warnings. Analyzer error diagnostics are also evaluated. Workspace loading alone is never accepted as evidence that generators ran.

Input provenance records project/framework/configuration, assembly identity, actual options/symbols, sorted source/additional/analyzer-config text hashes, metadata-reference hashes, generator types and source-project edges. These records do not enter business IR or infer package identity. The CLI adds `--project`, mandatory `--framework`, optional `--configuration`; explicit-file mode remains available and input modes cannot be mixed.

The cumulative and fixture incremental-generator projects target netstandard2.0 because Roslyn requires compiler extensions to use that host-compatible target; frontend/business targets remain net10.0/C#14. Exact tool dependencies and generated fixture inputs are locked and recorded independently.

## Core graph and call mapping

All selected declarations from every source compilation are discovered, including generated/partial/unused/nonpublic declarations. Syntax trees retain their owning compilation and semantic model. Canonical symbol keys include source assembly identity, full type identity and method signature, resolving imported source symbols without treating them as external DLL functions. Remaining normalized IR identity collisions diagnose both source declarations. Source owner modules are unchanged from D1.

D2 admits exact selected static non-generic calls with positional, ordinary by-value parameters. A target's signature creates a curried typed Reference and ordered Apply nodes (or typed Reference for a zero-argument value). Both private same-container and legal internal/friend cross-container calls retain Private wrappers. Namespace grouping modules remain Public; type-owned modules carry the source type's effective accessibility, including Private internal containers. Lookup reads complete definitions regardless of access; public specification filtering is independent. All selected bodies are validated, even unused callees, so calls cannot hide effects, checked arithmetic, M1/Decimal failures, or unsupported source. Cycles are rejected as MCS2203 until D14. Named/optional/params/ref and extended generic/dispatch contracts remain in their owning deliveries; D1 named record construction is retained.

An available source target outside selection fails MCS2201 with namespace/symbol/requester location; adding its namespace includes its unused admitted declarations too. An external metadata call fails MCS2202 unless a later delivery supplies an exact verified mapping/specification. Compiling an external call successfully is never purity evidence.
