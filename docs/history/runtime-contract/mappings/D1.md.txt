# D1 mapping and proof contract

- Owner: D1; baseline: .NET SDK 10.0.100 / reference pack 10.0.0 / C#14 / Roslyn 5.0.0; CLI target x64.
- Core API: `Frontend.Convert(CSharpCompilation, FrontendSettings)`; failed compilation/selection/validation/lowering yields diagnostics and no distribution.
- Source syntax discovers declarations/locations and unconditional checked exclusions. Symbols supply resolved identities, access, types, fields and constructor parameter ordinals. IOperation supplies expression semantics. CFG is unnecessary for this expression-only delivery; locals/blocks arrive in D3.

## Declarations and identities

All source types in case-sensitive selected namespace segments/descendants are discovered, independent of usage/access; overlapping selectors do not duplicate them. Partial declarations share the Roslyn type symbol. Record data belongs to its namespace (nested data to its enclosing type); methods belong to their declaring type module. The configured package's normalized segment prefix is removed only when it matches the complete owner prefix. Names follow upstream `[a-zA-Z][a-z]*|[0-9]+` tokenization. Dictionaries are emitted in Elm Name/Path lexicographic order; record type field lists preserve positional source order, record value dictionaries sort by Name.

An overloaded method's local name adds `__<generic arity>__<RefKind>_<fully qualified parameter type>` for each parameter (with no special-type alias abbreviations). For example the sample's overloads normalize to `echo0NoneGlobalSystemInt32` and `echo0NoneGlobalSystemBoolean`. Remaining normalized collisions diagnose both source locations. The table is shared across type definitions and reference resolution; type and value local identities are separate domains.

Effective public accessibility includes all enclosing types. Other declarations retain Private metadata; modules are namespace/container groupings with Public wrappers. Generated positional properties are represented as fields of the record alias, and compiler-generated constructors/equality/backing fields are plumbing, not standalone exports. Any explicit member outside the admitted forms is a rejection.

XML `<summary>` text is trimmed and stored as Morphir declaration documentation (or empty string when absent); absent module documentation is JSON null. Public package specifications filter private modules/types/values; private definitions remain in the complete package.

## Bound operations

| C# bound form | IR representation | Domain / failure policy |
| --- | --- | --- |
| `System.Int32`, `System.Boolean` | SDK `Basics.Int`, `Basics.Bool` reference | Full CLR value domains; all inputs already valid Int32/Bool |
| readonly positional record struct | Namespace/enclosing-type alias → Record | Positional int/bool data only; no explicit constructors, members with effects, field/default/attribute semantics or base lists omitted |
| static expression-bodied method | Typed definition, ordered named inputs, typed body | No generic/ref/default/params parameters, calls, effects or hidden return wrapper |
| int/bool literals; constant unary negative | WholeNumberLiteral / BoolLiteral | Negative constant evaluated exactly as compiler-validated Int32; general negation waits for D5 |
| string literal | SDK String.String + StringLiteral | Known-present literal only; no string inputs/fields/null/default extraction; M1 generalization D4 |
| parameter | Typed Variable | Source parameter order retained |
| resolved positional record property | Typed Field of subject | Value receiver, field symbol belongs to admitted record; no nullable dereference |
| resolved positional constructor, `new(...)`, named arguments | Typed Record; entries keyed by constructor parameter ordinal | Every argument lowered; all admitted arguments pure/total, so dictionary ordering cannot change observations; object initializers/default constructors with missing fields rejected |
| Int32 addition | Curried typed SDK Basics.add Apply/Apply | Both operands compile-time Int32 constants with sum in range, or one operand has proved zero constant value. Other additions rejected MCS2302; operands remain in IR |
| Int32 comparisons | Curried Basics.greaterThanOrEqual/greaterThan/lessThanOrEqual/lessThan/equal/notEqual | Exact resolved built-in Int32 operation; no overload-name-only matching or lifted/custom operators |
| Boolean conditional and/or | Typed IfThenElse | Left operand first; `&&` false branch False, `||` true branch True; RHS evaluation only when required |
| parentheses/identity conversion/unchecked syntax | Underlying operation | Identity only, no data conversion semantics guessed; actual IOperation checked arithmetic/conversions rejected |

No helper bodies or extra dependencies are needed in D1; every emitted SDK reference is listed above. Arbitrary calls and member effects remain rejected. Model-only dependency/specification/reference codecs are tested by the independent `model` Elm host distribution; this does not authorize dependency calls in business source.

## Proof and rejection evidence

Checked syntax (including constant-safe/unreachable expressions, blocks, and checked operators) is excluded by actual syntax kind; unchecked, comments, strings and `@checked` are distinct. Checked semantic operations retain the compilation/syntax overflow setting and fail. Unbounded addition, mutation/with updates, impure external reads, general nullable/string fields, Decimal and other unsupported operations/types fail as a whole.

The archived prototype's unbounded `a + b` cannot meet the D1 total-function contract (e.g. MaxValue + 1). The archived source/golden are unchanged: regression tests now assert rejection and independently compare the model-backed safe `a + 0` specialization with default-compiled Elm. Full wrap behavior stays in D5, as specified by the pre-D5 safety boundary.

D1 accepts no aliases/local mutation/possibly-null extraction/Decimal operation/failure-prone call. Their positive proof gates are not applicable yet; rejection fixtures ensure these cannot bypass safety. No unstated business bounds are assumed.

References: ordinary default-compiled Elm `eligibility`, `prefix`, `addition`; independent complete Elm codec host `private`, `sample`, `selection`, `outside`, `model`. The host includes actual bodies, qualified references, documentation, all access wrappers, typed attributes, and dependencies where present. [Provenance](../../fixtures/D1/expected/provenance.json) records all sources/compiler modes/hashes. All parsed distribution fields participate in parity; no JSON patching/normalization beyond object-property order and whitespace is allowed.
