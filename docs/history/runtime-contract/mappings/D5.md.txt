# D5 — numeric mapping and proof contract

Status: passed; final delivery gates are recorded in D5 state. Baseline: C# 14, Roslyn 5.0.0, .NET reference pack/runtime 10.0.0, fixed native x64. Decimal remains D6.

| Source domain | IR representation | Operations and boundaries |
| --- | --- | --- |
| Char, Byte/SByte, Int16/UInt16, Int32/UInt32 | SDK Basics.Int; full source range, including UInt32 through 4294967295 | Roslyn promotions determine operand/result types. Explicit casts, arithmetic, unary negation/complement and shifts wrap at the result width. Comparisons use exact mathematical values. |
| Int64/UInt64, IntPtr/UIntPtr | Compat.Integers.Integer | Full 64-bit range; native types are always 64-bit. Incompatible 32-bit compilations reject. |
| Int128/UInt128 | Compat.Integers.Integer | Full 128-bit range, two-UInt64 constructor, arithmetic and bitwise operations. |
| BigInteger | Compat.Integers.Integer | Arbitrary signed magnitude; no fixed-width wrapping. Integral and proved-finite floating constructors/conversions; exact Zero/One/MinusOne and Sign/IsZero/IsOne/IsEven properties. |
| Single/Double/Half | SDK Basics.Float with explicit precision helpers | Double uses binary64; Single operations round to binary32; Half operations use binary32 intermediate then binary16. Finite literals use FloatLiteral; nonfinite and negative-zero values are computed by complete helper definitions. |
| Complex | Compat.Floating.Complex alias, real/imaginary Double fields | Constructor, constants, real/imaginary properties, unary/binary arithmetic and equality. Complex/Double overloads retain the runtime's distinct operation order and nonfinite branches. |

`Compat.Integers.Integer` is `{ negative : Bool, digits : List Int }`: little-endian base-65536 limbs, each 0..65535; no leading zero limbs; zero has empty digits and false sign. UInt32 values and every intermediate small integer remain exactly representable in binary64. Wider source values never pass through a JSON whole-number literal or a floating value. `toSmall` is used only for a proved fixed result of at most 32 bits. Inputs must use this canonical representation and the declared source domain, just as ordinary Int32 inputs must satisfy their CLR range.

The original pure Elm libraries are in [eng/numeric-compat](../../eng/numeric-compat/). Their complete typed IR is generated explicitly, with hashes in [production provenance](../references/numeric-compat-provenance.json). The generated C# factory uses ordinary Classic model constructors and has no Json/runtime CLR dispatch dependency. On import, helper values are Private and representation aliases are Public. Every helper body, type, access wrapper and reference is included in complete fixture distributions. Owner collisions are source diagnostics. Unknown model nodes fail generation; no foreign helper stubs are introduced.

Integer division and remainder require a dominating nonzero proof. Signed fixed-width operations additionally exclude MinValue with divisor -1: the pinned CLR throws OverflowException for both division and remainder at that boundary. Narrowing BigInteger requires proved inclusive target bounds. BigInteger construction from floating values requires finiteness. Facts attach to immutable source snapshots, survive harmless local copies and are invalidated by reassignment; they cannot authorize a later different value. No default or success/error wrapper is invented. Nullable conversions/operators use D4 Maybe matching and retain absence; extraction still needs M1. Explicit checked syntax and semantic checked operations/conversions reject, including unreachable source.

Unchecked floating-to-integer casts follow the pinned runtime: Int32/UInt32/Int64/UInt64 saturate, NaN becomes zero; narrow primitive casts first convert to Int32 then wrap. Later .NET changes are not adopted. Integral-to-floating conversions use exact limb rounding with ties to even; Int128/UInt128 use their runtime's binary64 intermediate, while BigInteger truncates to its pinned binary64 significand before the target cast. Half uses the applicable binary32 intermediate. Constant conversions preserve Roslyn's constant semantics rather than assuming runtime cast equivalence.

The implementation was checked against the primary [floating conversion compatibility record](https://learn.microsoft.com/en-us/dotnet/core/compatibility/jit/9.0/fp-to-integer) and .NET v10.0.0 sources for [Int128](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Int128.cs), [UInt128](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/src/System/UInt128.cs), [Half](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Half.cs), [BigInteger](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Runtime.Numerics/src/System/Numerics/BigInteger.cs) and [Complex](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Runtime.Numerics/src/System/Numerics/Complex.cs). Compatibility algorithms here are original Elm implementations; upstream implementation text was not copied.

Independent references include ordinary Elm wrapping/helpers and a complete Elm codec host for all-family source and the cumulative project. The host uses the pinned algebra and unmodified codec, with independently authored business bodies. It never reads frontend output. The BigInteger range fixture resolves comparison's other operand to Int64; its constant representation follows that bound symbol. Earlier D1–D4 references remain frozen. Validation never regenerates expected JSON.

Behavior evidence is separate from parity: NumericTests, FloatingTests, ComplexTests, NullableNumericTests, NumericFixtureTests, NumericConversionTests and NumericSafetyTests compare emitted CLR behavior with evaluated complete IR, including extrema, promotion, shifts, >53-bit values, 128/256/300-bit values, rounding, saturation, nonfinite values, signed zero and missing values. `node eng/check-numeric-compat.mjs` independently compares compiled Elm helper arithmetic and JSON limb transport with native JS BigInt over deterministic boundary/random cases. Final gate results and remaining catalog work are recorded in [D5 state](../deliveries/D5-state.md).

Numeric language/domain and exact listed member support is recorded separately from full framework API closure. [numeric-members.json](../catalogs/numeric-members.json) inventories all pinned public declared symbols. It retains generic factories, Decimal, arrays, owned increments, object overloads and remaining pure numeric APIs under their prerequisite/final closure deliveries. D18.4 remains responsible for complete-fixed-catalog closure, as with D4 String APIs; these are not silently excluded or labelled supported. D5's assigned child gates cover every numeric family and the explicit numeric forms above.
